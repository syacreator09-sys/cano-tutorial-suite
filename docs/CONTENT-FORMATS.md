# Formatos editoriales de CANO Digital

CANO Digital no será un canal de cursos. Será un canal digital de descubrimiento, prueba y recomendación de herramientas, repositorios, modelos y automatizaciones.

La Suite debe seleccionar el formato mínimo necesario para explicar cada tema. Un tutorial completo solo se produce cuando la audiencia necesita ejecutar pasos exactos.

## Distribución editorial inicial

| Formato | Participación sugerida |
|---|---:|
| Recomendación de repositorios y herramientas | 35% |
| Novedades y descubrimientos | 20% |
| Pruebas reales y “¿sí funciona?” | 20% |
| Comparaciones y decisiones de compra | 15% |
| Tutoriales exactos paso a paso | 10% |

## 1. Repositorio recomendado

**Objetivo:** explicar qué hace, para quién sirve, requisitos y por qué vale la pena revisarlo.

**Duración:** 35–75 segundos.

**Estructura:**

```text
Hook
→ problema que resuelve
→ tres capacidades verificadas
→ requisitos o limitación principal
→ para quién sí / para quién no
→ CTA al repositorio o análisis completo
```

**Producción:**

- HeyGen: avatar CANO presenta y concluye.
- Playwright: captura README, estructura y demo disponible.
- Higgsfield: hook visual y metáfora del resultado.
- Compositor: zoom, flechas, nombre del repositorio y CTA.

No requiere tutorial completo.

## 2. Nueva herramienta en 30–45 segundos

**Objetivo:** presentar rápidamente una función nueva o una plataforma emergente.

**Estructura:**

```text
Qué acaba de aparecer
→ qué promete
→ función principal
→ limitación o costo
→ por qué importa
```

Puede producirse con HeyGen + capturas + Higgsfield sin grabación continua.

## 3. ¿Realmente funciona?

**Objetivo:** verificar una promesa concreta.

**Duración:** 60 segundos a 3 minutos.

**Estructura:**

```text
Promesa
→ prueba definida
→ ejecución real
→ resultado
→ errores o límites
→ veredicto
```

Playwright ejecuta y registra la prueba. HeyGen explica el criterio. Higgsfield muestra el problema, el caso de uso o el resultado de forma visual.

## 4. Comparación para decidir

Ejemplos:

- Claude Code vs Codex.
- HeyGen vs Higgsfield.
- Repositorio A vs repositorio B.
- Plan gratuito vs pagado.

**Estructura:**

```text
Decisión concreta
→ criterio 1
→ criterio 2
→ costo o dificultad
→ mejor opción por perfil
```

No convertir la comparación en una lista genérica. Debe responder una decisión real.

## 5. Caso de uso digital

**Objetivo:** mostrar lo que se puede construir sin enseñar cada clic.

Ejemplos:

- Crear un agente de WhatsApp.
- Convertir un PDF en video.
- Analizar un video con Claude.
- Construir UGC con avatar.
- Crear una fábrica de Shorts.

**Producción:**

- HeyGen cuenta el caso.
- Higgsfield muestra escenas, producto y resultado.
- Playwright aporta dos o tres evidencias reales.
- El compositor presenta el flujo completo.

## 6. Tutorial exacto

Solo se usa cuando el valor depende de ejecutar una secuencia precisa.

**Ejemplos:**

- Instalar un repositorio.
- Configurar un MCP.
- Conectar una API.
- Resolver un error.
- Reproducir una automatización.

**Producción:**

```text
Playwright: ejecución y captura exacta
HeyGen: explicación del avatar CANO
Higgsfield: hook, contexto y resultado
Compositor: zoom, cursor, flechas, capítulos y subtítulos
```

## 7. Lista semanal de descubrimientos

**Objetivo:** agrupar 3–5 novedades verificadas.

Cada elemento recibe:

- una frase de problema;
- una capacidad;
- una limitación;
- un CTA para guardar o comentar.

El largo semanal puede convertirse en varios Shorts mediante AI Clipping.

## Matriz para elegir formato

| Necesidad | Formato |
|---|---|
| Solo informar qué existe | Nueva herramienta |
| Ayudar a decidir si vale la pena | Recomendación |
| Comprobar una promesa | Prueba real |
| Elegir entre opciones | Comparación |
| Mostrar un resultado sin enseñar cada clic | Caso de uso |
| Ejecutar pasos que deben ser exactos | Tutorial |

## Regla de producción sin grabación manual

CANO no graba cámara, voz ni pantalla manualmente.

```text
ChatGPT / Claude
→ investigación, formato, hook y guion

/watch
→ análisis de videos de referencia cuando aplique

Playwright
→ capturas, pruebas y recorridos reales

HeyGen
→ avatar, explicación y CTA

Higgsfield
→ hooks, B-roll, UGC, producto y escenas conceptuales

CANO Hybrid Composer
→ master horizontal, vertical y cuadrado
```

## Entregables por una investigación

Una sola herramienta o repositorio puede producir:

```text
1 Reel de recomendación
1 Short de capacidad principal
1 pieza “¿sí funciona?”
1 comparación breve
1 carrusel resumen
1 video largo solo cuando el tema lo justifique
```

No se deben producir todas las variantes automáticamente. El agente selecciona las que aporten un ángulo distinto y evita repetir el mismo guion con diferente duración.

## Criterios de publicación

Antes de producir:

1. El repositorio o herramienta existe y está accesible.
2. Las funciones principales fueron verificadas en README, documentación o prueba.
3. Se identifica fecha, versión y limitaciones relevantes.
4. El contenido aporta análisis propio y no copia al creador original.
5. El CTA coincide con el objetivo: guardar, comentar, visitar, comparar o probar.
